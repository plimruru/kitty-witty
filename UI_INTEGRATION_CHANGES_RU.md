# Подключение UI к игре

Работа выполнена в ветке `CherryLinz`.

## Изменённые файлы

### `src/scenes/base_scene.ts`

- В `preload()` добавлена загрузка всех PNG-ресурсов UI и карты.
- Компактное меню создаётся во всех сценах, которые наследуются от `BaseScene`.
- Рюкзак и дневник читают актуальные данные из общего состояния игры.
- Карта отмечает текущую сцену и вызывает реальный переход `scene.start()`.
- Пока открыто модальное окно, движение игрока останавливается.
- При завершении сцены UI корректно уничтожается вместе с обработчиками.

### `src/main.ts`

- Запуск Phaser ожидает загрузку пиксельного шрифта, поэтому текст UI сразу
  отображается нужным шрифтом.

### `src/ui/game_ui.ts`

- Добавлен признак открытого модального окна для блокировки управления игроком.
- Компактное меню автоматически сворачивается при открытии окна.

### `src/ui/game_ui_state.ts` (новый файл)

- Добавлен типизированный мост между игровой механикой и UI через Phaser Registry.
- Состояние сохраняется при переходах между сценами.
- Добавлены функции `getGameUIState()`, `setGameUIState()` и
  `getMapLocationsForScene()`.

Игровая механика может обновить данные так:

```ts
setGameUIState(scene, {
    inventory: inventoryManager.getView(),
    notebook: journalManager.getChapterView(),
    unlockedLocations: progressManager.getUnlockedLocationKeys()
})
```

UI только отображает эти данные. Добавление предметов и изменение прогресса
остаются ответственностью игровой механики.

### `src/ui/index.ts`

- Экспортирован новый мост состояния, чтобы механика могла импортировать его
  через `../ui`.

## Проверка

- Выполнена production-сборка командой `npm run build-nolog`.
- Выполнена отдельная проверка типов изменённого TypeScript-кода.
- В браузере проверены загрузка `classroom`, открытие меню и карты, отметка
  текущей локации и переход карты в `garage`; ошибок в консоли нет.
